## 二、代理层架构类

### X1. 代理层三平台域名铁律

| 项目 | 内容 |
|-|-|
| **来源** | HY(1.1/1.2)、RL(#12)、CC(#20/#21)、KK(M-07/M-12)、YY、ZM(#4) |
| **问题描述** | 所有广告平台 API 均须走 代理层域名，不可直连官方；直连报 token 畸形 / 190 |
| **请求方式** | Meta / Google / TikTok API |
| **报错返回** | 直连官方：`code 190 Malformed access token`；代理层：`40100 token失效` |
| **是否解决** | ✅ |
| **解决方案** | 域名铁律：Meta 走 `[Meta代理域名]`；Google 走 Google 代理层；TikTok 走 TikTok 代理层。**token 一律放 URL query（Meta）/ Header（TikTok），不放 body** |
| **类型** | 代理架构 |

### X2. 代理层错误码语义（40100 / 40105）

| 项目 | 内容 |
|-|-|
| **来源** | CC(#20/#21)、KK(M-12)、JYY(#14) |
| **问题描述** | 代理层返回的错误码与 Meta 原生错误码语义不同，初期误判为权限问题 |
| **请求方式** | 经代理的 POST 请求 |
| **报错返回** | 代理层 `code 40100` = token 失效或位置错误（≠ Meta 原生 190） |
| **是否解决** | ✅ |
| **解决方案** | 排查顺序铁律：遇 40100 先查 token 是否放 body（M2）→ 再查 token 是否过期 → 最后才怀疑写权限（M5）。40105（TikTok）= Access-Token header 缺失 |
| **类型** | 代理层机制认知 |

### X3. 代理 Token 有效期短、需人工刷新

| 项目 | 内容 |
|-|-|
| **来源** | KK(M-07)、JYY(#6/#7)、YY(#9/#10) |
| **问题描述** | 代理层 token 有效期约 3 天，AI 7×24 场景下频繁过期中断 |
| **请求方式** | [代理工具] project account-token |
| **报错返回** | token 过期 |
| **是否解决** | ✅（人工刷新）/ 机制未优化 |
| **解决方案** | 执行 `[代理工具] project account-token` 重拉 token 写入 ad_tokens.json。**根因：代理层 token 续期机制未针对 AI 长时运行优化**，当前依赖人工/定时触发 |
| **类型** | 授权机制限制 |

## 三、Token 授权体系（单点故障）

### X4. Token 依赖单一授权人 —— 系统级单点故障

| 项目 | 内容 |
|-|-|
| **来源** | JYY(#6)、YY(#9)、KK(M-06)、MM(#5) |
| **问题描述** | 广告账户 token 由单一授权人（授权管理员 / 授权管理员 / 授权管理员 / 授权管理员等）个人 Meta 账号签发，该账号被封 / 改密 / 权限变更即导致名下**所有账户** token 全线失效 |
| **报错返回** | `code 190 subcode 464` user not confirmed / OAuthException |
| **是否解决** | ✅（换号 / 重授权可恢复）；MM 的 AMZ EU 属长期反复 ❌ |
| **影响时间线** | 7/11 客户A 6 账户全失效→7/14 恢复；7/12\~7/13 PK 换号；AMZ EU 截至 7/30 仍反复 |
| **解决方案** | 短期：由 BM 其他管理员重授权 / 换绑有权限的账号刷新 token。**长期建议：建立多授权人冗余机制，避免单点；关键账户 token 由 ≥2 人授权** |
| **类型** | 授权体系架构缺陷 |

## 八、LAA 多任务使用反馈（2026-08-20 同事）

> **说明**：本节汇总近期使用 LAA 建多任务（日数据监控 / 周报更新 / 广告调优等）过程中反馈的问题，主线为 **AI 记忆与任务状态持久化不稳定**，附截图佐证。反馈人：同事；技术侧：芦直属上级 / 平台管理员。

### X16. 记忆与规则沉淀不稳定（已确认规则频繁遗忘）

| 项目 | 内容 |
|-|-|
| **来源** | 同事（LAA 反馈 1、6） |
| **问题描述** | 之前已明确、反复执行过的规则，现在比较频繁地会忘，需人工重复提醒和校验，浪费大量时间；总体人工复核成本比之前更高 |
| **造成原因（推测）** | 规则依赖上下文/软记忆，跨会话未稳定加载；长对话中早期规则被挤出上下文窗口；规则未固化为系统级硬约束 |
| **是否解决** | ❌ 待优化 |
| **解决方案（建议）** | 高频关键规则从"软记忆"提升为"硬约束"：沉淀到工作区规则文件，任务启动强制加载 + 执行前 checklist 校验（参照 X15 铁律化思路） |
| **类型** | AI 记忆 / 规则持久化 |

### X17. 读取与理解准确度下降（多次上错）

| 项目 | 内容 |
|-|-|

### X22. 工作流写入文档后修改链路过长（诉求：项目包随时调用）

|-|-|
| **来源** | 同事（LAA 反馈 5-补充） |
